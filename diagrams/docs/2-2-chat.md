---
title: 2-2 AIチャット
---

チャットは接続AIを実行体に持つ対話面です。

## 基本操作

- **新規チャット** — チャットヘッダまたは処理状況ボード上部の
  「＋ 新規チャット」。cwd はカレント repo の path
- **切替** — chat の切替は処理状況ボードのカードで行う。
  ヘッダの「◀ 戻る / 進む ▶」は処理状況ボードと同じ並びで
  前後の chat を順に表示する
- **送信** — Enter（Shift+Enter で改行）。実行中の送信は追加指示（steer）になる
- **修正** — 最後の送信を ↑ キーまたは ✎ で取り消してやり直し
- **中断 / リセット** — 実行中断 / セッションを畳んで次の送信で新規開始
- **削除** — タイトル左のボタン。処理が終わった chat でのみ表示
  （実行中・検証中・要対応では非表示）。内容を確認してからその場で削除
- **変更復元** — その chat が変更したファイルを、選択した turn 時点の
  スナップショットへ復元
- **添付** — 📎 ボタンまたは貼り付け。`chat-uploads/` に保存

## 処理モード

入力欄の select で切替（chat ごとに永続化）:

- **直接** — 従来どおり逐次処理（分割子チャットもこの固定モード）
- **並列**（既定） — `kasugai-split` で課題を分割し子チャットを自動起動。
  各子の最終回答はダイジェストとして親へ集約される

## 他のタブ・表示

- **console タブ** — 実行体の stderr・control 自身の stdio を表示
- **リポジトリ確認バー** — prompt が他 repo 向けと判定されると確認バーが出る
  （切替えて送信 / このまま送信）
- **ファイル競合** — 他 busy chat が触れているファイルに触れる指示は
  実行待機（waiting）になり、ブロッカー解除で自動再送される

## セッション再接続

ACP 型の実行体はセッション常駐です。control 再起動後は resumable chat を
自動で `session/load` 再接続し、処理状況「再開可」列の「再開」ボタンでも
手動再接続できます。処理状況ボード上部の「処理再開」ボタンは、止まった
処理（再開可・検証待ち・ブロッカーが消えた実行待機）を一括で再開します
（再開可 chat には再接続後に中断作業の続行 prompt を送ります）。
